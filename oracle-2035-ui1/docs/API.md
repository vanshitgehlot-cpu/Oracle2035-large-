# ORACLE 2035 — API Contract Specification

## Base URL & Headers

All API endpoints are served from port `3000`.

- `Content-Type: application/json`
- `X-Request-Id: <uuid>` (Generated by client or injected automatically by server)
- `X-RateLimit-Limit: 60`
- `X-RateLimit-Remaining: <count>`

## 1. Health & Readiness Probes

### `GET /api/health`
Checks container health.
- **Response `200 OK`**:
```json
{
  "status": "ok",
  "timestamp": "2026-08-25T06:45:00.000Z",
  "version": "2.0.0-LOCKED"
}
```

### `GET /api/ready`
Checks container readiness.
- **Response `200 OK`**:
```json
{
  "status": "ready",
  "timestamp": "2026-08-25T06:45:00.000Z",
  "version": "2.0.0-LOCKED"
}
```

## 2. Canonical Decision Analysis

### `POST /api/analyze-decision` (Alias: `POST /api/v2/analyze-decision`)

> **Note:** `/api/analyze-v2` DOES NOT EXIST. The canonical endpoint is `/api/analyze-decision`.

Executes authoritative schema validation, deterministic Decision DNA analysis, scenario modeling, SHA-256 hash generation, and optional AI synthesis.

## 3. Supplementary Endpoints

### `POST /api/v2/validate-decision`
Pre-flight endpoint to strictly run `decisionSchema.ts` validation without executing the engine.
- Accepts `V2DecisionPayload`.
- Returns `{ valid: true, data: { ... } }` or `{ valid: false, errors: [ ... ] }`.

### `POST /api/simulate`
Legacy V1 adaptation endpoint. DO NOT use for new V2 interfaces.

### `POST /api/avatar-ask` (Alias: `POST /api/chat-future-self`)
Interacts with the Future Self AI context generation.
- Request: `{ question: string, userContext?: any, simulation?: any, profile?: any }`
- Response: `{ answer: string, reply: string }`

## 4. Error Taxonomy

All error responses strictly follow the standard JSON envelope:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Validation failed against the canonical V2 decision schema.",
    "details": [
      { "field": "decision.decisionStatement", "issue": "Required field missing." }
    ]
  }
}
```

### Standard Error Codes

| Error Code | HTTP Status | Description |
| :--- | :--- | :--- |
| `VALIDATION_FAILED` | `400` | Missing or invalid required schema fields |
| `UNAUTHORIZED_COMPUTED_FIELD` | `400` | Client attempted to inject computed scores or hashes |
| `MALFORMED_JSON` | `400` | Unparseable or invalid JSON syntax |
| `PAYLOAD_TOO_LARGE` | `413` | Request body exceeds the 2MB limit |
| `RATE_LIMIT_EXCEEDED` | `429` | Exceeded 60 requests per minute per IP |
| `SERVER_CALCULATION_ERROR` | `500` | Internal computation failure |

## 5. Epistemic Boundary Notice
When displaying results, you must include the mandatory epistemic boundary notice:
> *"Evidence confidence reflects evidence quality. It does not represent the probability that an ORACLE conclusion is correct."*
